# 四季旅行规划助手（TravelSeasonPlanner）

基于 **Nexent v2.8.2** 构建的中文旅行规划智能体。输入目的地与出行时间，输出分时段的可执行行程、预算表，以及**按季节、天气与活动类型定制的装备与着装清单**。

与只给行程的规划助手不同，它把「穿什么、带什么」当作一等输出：会先查目的地当期天气，再据此推导分层穿衣、鞋履、雨具与随身物品，并区分必备与可选、单独标注老人与儿童。

> 本目录中的 `agent.json` 由 Nexent 平台导出后做过脱敏，不包含原开发者的租户标识、邮箱或 API Key。导入后需自行配置模型与搜索工具的密钥。

## 与本仓库 TravelPlanner-Agent 的区别

`通用智能体/其他/TravelPlanner-Agent` 与本智能体同属旅行规划品类，但侧重点不同，可按需二选一或同时保留：

| 维度 | TravelPlanner-Agent | 本智能体 |
| --- | --- | --- |
| 输入重点 | 出发地、人数、预算、兴趣偏好 | 目的地、出行时间、活动类型 |
| 行程编排 | 按天组织景点与餐饮 | 按「天 × 上午/中午/下午/晚上」分时段，标注交通耗时与门票 |
| 装备与着装 | 未覆盖 | **核心能力**：分层穿衣、鞋履、雨具、随身物品，分必备/可选/特殊人群 |
| 天气处理 | 检索后参考 | **以天气为排程依据**：晴天赶路、雨天换室内、按降水时间调整户外段 |
| 预算 | 分项估算 | 分项估算 + 合计 + 人均，注明估算口径 |
| 不确定处理 | 提示核实 | 输出末尾单列「未核实项」清单，逐条列出未取得实时确认的字段 |

如果你只需要一份常规行程，用 TravelPlanner-Agent 更直接；如果你在意「这趟该带什么、天气变了怎么办」，本智能体的输出更有用。

## 功能

- **需求确认**：目的地为必填，缺失时先询问；尽量补齐出行时间、天数、人数与人群构成、预算、活动类型、出发地。信息不全时先给框架，并把假设单列出来请用户确认。
- **实时核验**：涉及天气、景点开放状态、门票、交通班次、节庆时调用 `deepseek_search`；检索失败会明说「未能获取实时信息」，不假装知道。
- **分时段行程**：每天按上午—中午—下午—晚上编排，给出景点游览时长、用餐安排、交通方式与耗时、门票费用，同区域景点相邻安排以减少折返。
- **装备清单**：依据当期气候与行程强度给分层穿衣、鞋履、防晒保暖、雨具、随身物品与证件；区分必备/可选，对老人儿童单独标注。
- **预算表**：分项到往返交通、住宿、餐饮、门票、市内交通、备用金，给出合计与人均。
- **风险提醒**：需预约项目、天气敏感日、封山枯水期、周一闭馆等，并单列未核实项。

## 运行环境与依赖

| 项目 | 配置 |
| --- | --- |
| 智能体开发平台 | Nexent v2.8.2（本项目开发与测试环境） |
| 智能体变量名 | `travel_season_planner` |
| 大语言模型 | `DeepSeek V4 Flash`（需在目标 Nexent 实例中配置可用模型，导入后按提示映射） |
| 内置工具 | `deepseek_search`（需自行申请 DeepSeek API Key，并在工具配置中填入） |
| 知识库 / 自定义 Skill / MCP | 当前版本未使用 |

`deepseek_search` 走 `https://api.deepseek.com/v1/tools/search`，与 DeepSeek 对话模型共用同一把 API Key，无需额外申请搜索服务。

## 导入与配置

1. 在目标环境部署或登录 Nexent，获得智能体开发权限。
2. 进入 **智能体开发 → 导入**，选择本目录中的 `agent.json`。
3. 导入后按提示选择目标环境中可用的大语言模型（原文件中的模型 ID 属于开发环境，不能直接沿用）。
4. 进入 **工具管理 → `deepseek_search` → 配置**，填入**自己申请**的 DeepSeek API Key。导出文件中的 `deepseek_api_key` 已置空，不填则无法联网检索，智能体会退化为仅凭常识作答。
5. 配置完成后进入调试页，用下方示例问题验证一次检索链路。

## 使用示例

**输入**

```
帮我规划 3 天杭州行程，10 月底出发，两个人，预算 3000，喜欢徒步和逛老街
```

**实际输出结构**（Nexent v2.8.2 实测，2026-10-30）

1. **假设先行**：因未提供出发地，按「中距离高铁人均 600 元」预留；未提供人群构成，按两名成年人中等体能设定，并说明「告知后可重排」。
2. **行程概览表**：D1 晴天逛清河坊与南宋御街；D2 多云转雨，上午走九溪十八涧—龙井村—十里琅珰，下午早点收；D3 小雨，改运河边室内为主的桥西历史街区与小河直街。
3. **分时段明细**：每段标注时长、交通方式与票价，例如「地铁 4 号线水澄桥站 B 口转公交，地铁+公交约 6 元/人」。
4. **装备清单**：依据「白天 25–27℃、早晚 14–16℃、11/1 后期起降水降温」，给出速干长袖 + 薄抓绒 + 轻薄防风外套的分层组合、防滑徒步鞋（九溪需多次踩石过溪）、折叠伞 + 轻便雨衣（山脊风大伞不好用）、20–25L 双肩包与防雨罩等，并单列带老人/带儿童的调整方案。
5. **预算表**：往返交通 1200、住宿 800、餐饮 500、门票 100、市内交通 200、备用金 200，合计 3000，人均 1500，并注明可优化项。
6. **风险与未核实项**：九溪涉水段雨天风险、真际院 16:30 关门、茶田礼仪、周末住宿紧张、周一博物馆闭馆；末尾明确列出「云栖竹径门票金额、桥西博物馆开放时间未取得实时确认，以官方公示为准」。

**检索行为**：该轮实际触发 3 次检索，分别取得杭州轻徒步路线清单、老街开放信息、以及当日发布的冷空气预报新闻（2026-10-30），并在正文中以 `[[o1]]` 形式标注来源。

## 测试情况

- 测试环境：本地 Docker 部署的 Nexent v2.8.2，模型 `DeepSeek V4 Flash`
- 测试时间：2026-10-30
- 测试项：需求缺省时的追问与假设声明、`deepseek_search` 检索链路、分时段行程生成、装备清单按天气分层、预算分项求和、未核实项标注
- 结果：单轮 38 秒完成，检索命中 3 条相关结果，输出 5 个章节完整，预算分项与合计一致
- 已知限制：强依赖检索质量，检索失败时装备建议会退化为按季节常识推断；门票与开放时间类信息需用户二次确认
