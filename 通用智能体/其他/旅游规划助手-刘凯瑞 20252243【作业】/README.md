# 旅游规划助手-刘凯瑞 20252243【作业】

一个面向自由行的行程规划智能体：先问清关键信息，再输出可直接照着走的逐日行程、住宿建议、预算拆分和备选方案。

## 适用场景

- 自由行行程规划（国内 / 出境）
- 亲子游、情侣游、朋友结伴、带老人出行
- 想在固定预算内安排路线，或对现有行程做优化

## 能力特点

1. **先追问再规划**：目的地、日期天数、人数构成、预算口径、兴趣偏好、体力强度、是否自驾，信息不足时一次最多追问 3 个关键问题，避免给出泛泛的通用攻略。
2. **结构化输出**：行程总览 → 逐日安排（上午/下午/晚上，含交通方式与耗时、门票、步行强度）→ 两档住宿区域建议 → 预算拆分表 → 雨天备选与避坑提醒。
3. **可执行性约束**：每天不超过 4 个主要景点、相邻景点合并同一天、预留用餐与移动缓冲；不编造票价、营业时间和班次，不确定的信息明确标注「出发前请核实」。
4. **预算兜底**：预算明显不足时直接指出，并给出降级方案（换住宿类型、减少付费景点、压缩天数）。

## 使用示例

| 场景 | 提问示例 |
|------|----------|
| 出境自由行 | 下个月去日本关西 6 天，两个人，预算 1.5 万（不含机票），喜欢人文和美食，帮我排个行程 |
| 亲子游 | 国庆带 5 岁小孩去成都 4 天，不想太累，怎么安排 |
| 自驾路线 | 云南 8 天自驾，昆明进丽江出，路线怎么走比较顺 |

## 配置说明

- **模型**：默认使用 `deepseek-flash`（对话型 LLM）。导入后如本地模型名不同，请在「智能体开发 → 模型配置」中重新选择模型。
- **工具 / Skill**：无依赖，导入即用。
- **知识库**：未绑定。如需结合自有攻略、报价单或线路库，可在平台中新建知识库并挂载（需配置 Embedding 模型）。

## 提示词设计要点

- 角色设定为「10 年经验的自由行定制顾问」，明确工作流程与输出结构。
- 硬性禁止编造实时信息（票价、班次、营业时间），降低误导风险。
- 强制控制每日景点数量与移动半径，避免「打卡式赶场」。
