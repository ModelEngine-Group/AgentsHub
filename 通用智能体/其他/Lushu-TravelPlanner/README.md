# 旅游规划助手（Lushu · Travel Planner）

基于 **Nexent v2.8.3** 构建的中文旅游行程规划智能体，角色设定为从业十年的旅游规划师「路书」。

它的核心设计不是"更会写行程"，而是**不编**：信息不全时只提问、不假设；查不到实时数据时明说、不硬凑；预算必须自洽可核对。

> 本目录中的 `agent.json` 由 Nexent 平台导出，并在发布前做了脱敏：不含原开发者的租户标识与任何 API Key。导入后需要自行配置模型与两个 MCP 服务的密钥。

---

## 为什么值得单独提交：三个工程约束

多数旅游类智能体的通病是"太想给出答案"——用户只说目的地，模型就自动补上出发地、日期、预算，然后一本正经地输出一份看似完整的行程。这种做法在真实使用中很危险：出行方案建立在虚构前提上。

本智能体用提示词硬约束解决了三个具体问题。

### 1. 五项必填缺失 → 本轮只能提问

出发城市、出行日期、天数、人数构成、总预算，五项中任一缺失，本轮回复**只能是提问**，且明确禁止四件事：

- 禁止输出行程、Day 表格、时间安排、价格、预算分解
- 禁止调用任何工具（天气、搜索、地图这轮都不要查，避免"边查边规划"变相绕过）
- 禁止出现"假设""按默认""如果你没说我就……"这类表述
- 限制在 60 字以内，不解释原因、不预告后面要做什么

只有用户明确回"都行/随便/你定"，才可按常规安排，且必须在第一行声明所采用的默认值。

### 2. 真实地理数据优先于文本搜索

接入**高德地图 MCP（amap-maps）**的 12 个工具，用于拿到真实 POI 坐标、换乘路线、周边餐饮住宿、城市天气；再用 **Tavily** 补齐门票价格、开放时间、预约要求。

分工是明确的：地图负责"在哪里、怎么去、多久到"，搜索负责"多少钱、几点开、要不要预约"。价格与营业时间一律来自搜索，不靠模型记忆。

### 3. 工具调用纪律

- 一轮只调用一个工具，等结果回来再决定下一个查什么（并行调用容易让模型退回原生标记格式，导致输出污染）
- 某工具报错（403／额度不足／超时／参数错误）不重试同一个，换下一个可用工具
- 连续两次失败就停止检索，用已有信息作答并注明"部分信息未查到实时数据"
- 查不到的项写"未查到实时数据，建议出行前核实"，严禁凭记忆编价格、班次、开放时间

## 导入与配置

1. 部署或登录 Nexent（v2.8.x），获得智能体开发权限。
2. 进入 **智能体开发 → 导入**，选择本目录的 `agent.json`。
3. 模型映射：导入时选择目标环境中可用的对话模型（原实例使用 `deepseek-chat`）。
4. 配置 MCP 服务（两处 URL 里的密钥是占位符，必须替换）：
   - `amap-maps` → `https://mcp.amap.com/mcp?key=<YOUR_AMAP_WEB_SERVICE_KEY>`
   - `tavily-search` → `https://mcp.tavily.com/mcp/?tavilyApiKey=<YOUR_TAVILY_API_KEY>`
5. 进入智能体的**工具管理**，确认上述工具已启用并绑定（导入后可能有部分工具为未启用状态）。
6. 用下方"使用示例"逐条回归，确认工具连通与提问约束均生效后再发布。

> **安全提醒**：不要把自己的 API Key、租户密码或登录令牌提交到仓库。若重新导出已配置的智能体，请再次检查 `mcp_info` 中的 URL 是否带密钥。

## 使用示例与预期输出

### 示例 1：信息不全时必须只提问

输入：`两个年轻人去仙女山两天一晚预算五百怎么规划`

预期：**不输出任何行程**，只反问缺失项，例如"从哪个城市出发？大概哪几天去（或哪个周末）？"

这一条是本智能体最关键的验收点。如果它直接开始规划，说明提示词没生效。

### 示例 2：补齐信息后先确认偏好

输入：`重庆大学，12月1日`

预期：确认"出发城市（重庆）、日期（12月1日）、两天一晚、两人、预算 500 元"已齐，再一次性问清交通方式、住宿档次、必去/不想去的地方、饮食忌口，并允许用户回"都行"。

### 示例 3：完整规划

输入：`都行`

预期：首行声明默认值（经济型住宿、公共交通、无特殊忌口），随后输出

- 往返交通方案（含耗时与票价区间）
- 分时段的 Day 1／Day 2 行程，景点之间标注交通方式与耗时
- 预算分解表：交通 / 住宿 / 餐饮 / 门票 / 市内交通 / 备用金
- **预算合计必须与 500 元对上**，并注明哪些数字是估算、哪些未查到实时数据

### 示例 4：多轮调整

在同一会话继续：`预算改成 400，其他不变`

预期：保留其余已确认条件，通过调整住宿档次或交通方式把合计压到 400 元内，并说明改了哪些项。

## 开发侧已验证的行为

在原始开发实例（Nexent v2.8.3 + deepseek-chat + 上述两个 MCP）上验证过：

- 单轮提问约束生效：信息不全时不调工具、不出行程
- 地图类工具返回真实坐标与路线（`maps_geo`、`maps_direction_transit_integrated`）
- 搜索类工具返回门票与开放时间（`tavily_search`、`tavily_extract`）
- 多轮对话中偏好确认与默认值声明按预期触发

**这些是原始实例上的结果，不等于这份脱敏文件在新环境导入后即可复现。** 请在自己的实例上重跑示例 1—4。

## 局限与说明

- 天气、票价、班次均为查询时点的信息，出行前请以官方渠道为准。
- 高德与 Tavily 均有调用额度限制，额度耗尽时智能体会降级为"标注未查到"，而不是编造。
- 不执行购票、酒店预订、付款等真实交易。
- 未接入实时余票与实时路况，交通耗时以地图规划值为准，节假日需自行留出余量。
- 提示词对"只提问"的约束依赖模型遵循度。若更换为遵循度较低的模型，建议把示例 1 加入回归用例。
