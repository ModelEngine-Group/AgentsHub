# 周末微旅行规划助手

把 1–3 天的周末短途出行，整理成一张可以直接照着走的行程卡：**少赶路、留空白、算清预算，并且每天都有 Plan B**。

这是一个刻意做“小”的 Nexent 智能体：不接 MCP、不挂知识库、不依赖自定义 Skill，只用一个 `agent.json` + 一段结构化提示词完成规划。适合作为第一次向 AgentsHub 提交智能体的最小范例，也适合直接导入后使用。

## 它解决什么问题

很多行程助手会把三天排成十个景点，最后变成“赶路 + 打卡”而不是旅行。这个智能体约束自己：

| 原则 | 具体做法 |
| --- | --- |
| 少赶路 | 同一天只在一个片区活动；跨区最多一次 |
| 留空白 | 每天预留 1 小时机动，不排密集打卡 |
| 算清预算 | 交通/住宿/餐饮/门票/其他五项，先求和再写合计 |
| 有备选 | 每天给雨天、排队、体力不支三个 Plan B |
| 不装实时 | 不编造车次、票价、余票、营业时间；统一标注“出行前核实” |

## 适用与不适用

**适合**

- 周末 1–3 天的城市周边游、短途高铁游、亲子/带父母的小长假
- 已经有目的地，只差“怎么排、花多少、下雨怎么办”
- 想先拿一版能执行的草案，再自己微调

**不适合**

- 需要实时比价、查余票、代订酒店/门票
- 多城市长线、跨境签证、自驾路书等复杂规划
- 对景点开放时间、交通班次要求 100% 准确的场景（请以官方渠道为准）

## 导入 Nexent

1. 打开 Nexent，进入 **智能体开发**。
2. 点击 **导入**，选择本目录的 `agent.json`。
3. 模型选择 **DeepSeek-V4.1-Flash**（JSON 已按显示名声明；若你的环境名称不同，导入后重新绑定即可）。
4. 保存后点击 **调试**，用下面的示例问题试一轮。
5. 确认输出结构、预算加总和 Plan B 都正常，再发布。

> 本智能体不包含任何工具调用，因此不需要配置 MCP、知识库或技能。导入时若平台提示“模型不存在”，在智能体编辑页重新选择当前环境的模型即可，其余配置不用改。

## 使用示例

**示例 1：两个人周末去苏州**

> 周六周日从杭州去苏州，两个人，预算 1500 元，不想太赶，想吃本地菜。

期望：按“杭州→苏州”大交通 + 苏州一个片区排两天；预算五项相加后给出人均和合计；每天有雨天/排队替代项；不编造具体车次和票价。

**示例 2：带父母，少走路**

> 北京出发，带爸妈去天津玩两天，人均 600 元，少走路。

期望：主动降低步行强度，景点集中在同一片区，预留午休；预算按两人一间房估算；提示无障碍、洗手间、休息点等注意事项。

**示例 3：一个人一日游**

> 上海周边 1 天，一个人，预算 300 元，想安静一点。

期望：推荐低强度、低消费的片区；按人均计算（住宿为 0 或注明不过夜）；给出返程时间底线。

## 输出长什么样

每次回答固定为七段：**行程卡 → 每日安排 → 预算 → 预约与避坑 → Plan B → 出发前确认 → 需要你确认**，开头先给一句结论。核心约束：

- 每日安排用时间块表格，写清交通方式与耗时区间，不写“随便逛逛”；
- 预算表先逐项相加，再写合计，并和用户预算比较；
- 不确定的实时信息统一写“出行前以官方最新信息为准”；
- 信息不足时最多问 3 个问题；用户说“你先安排”就直接给方案并列出假设。

## 设计说明

只用一个提示词，不意味着把规则堆长。这个智能体只做三件事：

1. **收口输入**：把“周末想出去”收敛成出发地、目的地、天数、人数、预算、限制六个槽位；
2. **约束输出**：用固定表格和“预算先加总”的硬规则，避免流水账和算错账；
3. **承认边界**：没有工具就明确说没有实时信息，把“核实”变成行程的一部分。

如果后续要扩展，优先级建议是：先加天气/地图 MCP，再加真实门票与营业时间查询；不要在提示词里假装这些能力已经存在。
