# 旅游规划助手

根据目的地、出行天数、人数、预算、出发地和旅行偏好生成个性化行程，支持根据用户反馈调整景点、路线和节奏。

| 项目 | 配置 |
| --- | --- |
| 内部名称 | `Travel_Planning` |
| 显示名称 | 旅游规划助手 |
| 发布包版本 | 1.0.0 |
| 导出环境 | Nexent v2.7.0 |
| 原配置模型 | `glm-5` |
| 最大执行步数 | 15 |
| 搜索工具 | Nexent 内置 `TavilySearchTool` / `tavily_search` |

## 功能

- 收集目的地、日期、人数、预算、同行人员、交通与住宿偏好、体力及饮食要求。
- 按天规划景点、美食、住宿区域与交通衔接，并给出预约和出行提示。
- 根据老人、儿童或轻松出游等需求调整行程节奏。
- 支持修改预算、增减景点、更换交通方式以及减少热门打卡点。
- 结合 Tavily 搜索核实公开信息，并对价格、开放时间、天气和政策等变化信息提示复核。

## 文件

```text
Travel_Assistant/
├── agent.json
├── README.md
└── CHANGELOG.md
```

`agent.json` 来自 Nexent 导出。本提交副本将 Tavily API Key 置空，将租户 ID、本机模型 ID 和按模型 ID 保存的空参数覆盖置为 `null`，保留原提示词、作者、模型名称及工具参数。内部 Agent ID 用于描述导出结构，导入时由平台处理。

## 导入与配置

1. 使用具备智能体开发权限的租户账号登录 Nexent。
2. 在模型配置中添加可用的对话模型并通过连通性检查。原环境使用 `glm-5`，导入时按目标环境可用模型重新绑定。
3. 在智能体开发页面选择“导入”，上传本目录的 `agent.json`。遇到重名提示时调整显示名称。
4. 打开导入后的“旅游规划助手”，检查模型绑定。
5. 在工具配置中找到 `tavily_search`，填入自己的 `tavily_api_key`。当前配置的 `max_results` 为 `5`，`image_filter` 为 `true`。
6. 保存后，在调试对话中执行下方用例，确认模型响应和搜索工具调用正常。

Tavily 需要有效的 API Key 和可访问其服务的网络。发布包中该参数为空，使用者需完成上述配置后验证联网检索。当前导出中的 `skill_names`、`managed_agents` 和 `mcp_info` 均为空，依赖清单以此配置为准。

## 使用示例

### 补充需求

输入“我想去桂林玩”。预期助手追问天数、人数、预算、出发地、交通偏好和同行情况，再组织行程。

### 完整行程

```text
我打算去桂林玩3天，一共2个人，总预算3000元，从重庆出发。
想看山水、吃本地菜，公共交通出行，节奏不要太赶。
请按天安排路线，说明交通、住宿区域及需要提前核实或预约的事项。
```

### 多轮调整

```text
调整刚才的行程，减少热门打卡点，增加本地美食和休息时间。
同行有老人，请降低步行强度，并标明需要重新核实的交通信息。
```

## 使用范围

输出用于行程参考。门票、交通班次、酒店价格、开放时间和出入境政策应在出发前通过官方渠道核实。境外行程会提示签证、出入境及当地安全信息。票务、支付和住宿预订由用户自行完成。
