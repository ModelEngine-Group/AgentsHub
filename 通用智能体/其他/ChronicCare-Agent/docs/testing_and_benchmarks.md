## 3.1 单元测试与静态检查

当前交付版包含431项默认单元测试、契约测试与集成测试，另有6项通过`real_integration`标记显式开启的真实集成测试。默认测试覆盖Open SQL安全预检、问题改写、Schema Linking、模板SQL、只读执行器、运行上下文、Agent路由、Supervisor编排、动态DAG、DataMate流水线状态与异常分支、疾病与共病聚合、图谱读写与查询辅助、MCP契约、聚合摘要与审计、NPU对比口径、报告入口、答案格式化和图表报告生成。真实集成测试覆盖已部署Tool Server只读接口、MCP JSON-RPC与工具分派、DataMate容器单行文件接入、Ascend NPU设备探测和最小张量计算。

```bash
python3 -m pip install -r requirements.txt
make quality
make coverage
```

真实服务与硬件测试默认跳过，显式执行方式如下：


真实集成测试仅调用只读服务接口；DataMate使用pytest临时目录中的单行CSV，NPU仅执行最小张量计算。测试结束后会删除容器内对应的临时工作目录。

最终结果为431项默认测试全部通过，6项真实集成测试全部通过，共437项；Ruff静态检查全部通过。完整机器可读证据包括`outputs/evaluation/pytest_report.xml`、`pytest_execution.log`、`coverage.json`、`ruff_report.json`、`ruff_execution.log`和统一摘要`test_execution_summary.json`；JUnit与日志中的本机主机名、用户名和绝对工作路径已做发布脱敏，测试结果本身未修改。启用真实集成测试后，按`analysis`、`kg`、`mcp_adapter`、`orchestration`、`runtime_common`、`tool_server`和`visualization`统一统计，语句与分支综合覆盖率为62.32%，其中语句覆盖率为65.61%，分支覆盖率为53.64%。重点模块中，MCP HTTP客户端、MCP Adapter客户端和问题流水线覆盖率均为100%，问题分类器为98.39%，动态DAG引擎为98.13%，图谱总览渲染为95.48%，图表渲染为93.20%，报告入口为91.49%，Supervisor编排为90.00%，查询规划（`orchestration/planner.py`）为86.49%，NPU runtime（`runtime_common/npu_runtime.py`）为86.36%，Open SQL工具服务（`tool_server/open_sql_tools.py`）为84.62%，DataMate流水线工具为81.82%，工具通用层为75.45%，NPU工具为62.88%，DataMate runner为55.32%，MCP聚合入口（`mcp_adapter/server.py`）为51.51%。

运行时会生成以下机器可读证据：

不支持问题子集共25题；按当前固定子集评测脚本口径，其Precision、Recall和F1均为100%。

唯一失败题为“统计就诊事件规模”：候选SQL将“规模”解释为去重患者数，返回2,000人；Gold口径统计去重就诊事件，结果为8,231次。该失败属于“患者人数”与“事件记录数”的语义口径差异，SQL本身通过Guard并成功执行。

该评测属于本地固定工程回归盲测。题集按复杂查询、LLM候选、模板、安全自然语言和不支持问题分组；Gold SQL仅由评测器在候选生成后执行，不进入模型提示词。生产路由不包含题目ID、完整题目或Gold SQL的硬编码。

## 9. CPU/NPU测试方法

证据：

- `outputs/evaluation/npu_operator_benchmark_report.json`
- `outputs/evaluation/npu_operator_benchmark_report.md`

`npu_readiness_report.json`反映通用CPU release容器的本地依赖探测结果；正式NPU基准来自具备完整CANN、`torch_npu`和模型权重的外部DataMate NPU环境，正式报告记录`fallback_used=false`。两者对应不同运行环境，不构成状态冲突。

### 9.1 公平性口径

- 输入：CPU和NPU的2,048条测试使用同一批样本。
- CPU：64线程，batch size 64。
- NPU：单张Ascend 910B3，batch size 1024。
- 序列长度：64。
- 预热：CPU和NPU各1次，预热耗时排除在正式测量之外。
- 计时：CPU 2,048条、NPU 2,048条和NPU全量分别真实计时。
- 采样：NPU 2,048条和NPU全量分别启停独立资源采样器。
- 重复：同一批2,048条样本在物理6号Ascend 910B3上独立执行5轮；表格采用耗时算术平均值，加速比=CPU平均耗时/NPU平均耗时。
- CPU功耗：未采集整机功耗，因此不做CPU/NPU严格能效对比。

## 11. 结果解释边界

- 不跨NPU运行批次混用耗时、吞吐量、功耗或加速比。
- 不把CPU规则召回耗时计入BGE同样本加速比。
- 不把CPU进程时间折算的等效核数当作整机功耗。
- 不把工程回归准确率表述为临床诊断准确率。
- 不展示内部图谱质量评分。
- 所有医疗相关结果均为辅助分析，不构成诊疗建议。
