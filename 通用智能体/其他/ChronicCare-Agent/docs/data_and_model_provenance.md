# 数据与模型来源及治理边界

## 1. 数据性质

当前数据版本标识为`synthetic_chroniccare`。数据参考真实慢病随访业务的字段结构、业务关系和合理取值范围，采用程序化规则与固定随机种子合成，不来源于真实患者个体或原始病历，也不包含可识别的真实患者身份信息。该数据用于工程功能、统计口径和系统性能验证，不应被解释为真实流行病学调查、临床试验或医疗机构生产数据。

## 2. 当前数据规模

| 数据项 | 数量 |
| --- | ---: |
| 患者 | 2,000 |
| 随访记录 | 8,231 |
| 检验记录 | 131,323 |
| 用药记录 | 18,248 |
| 慢病类型 | 20 |
| 图谱节点 | 197,404 |
| 图谱边 | 396,928 |

当前20种疾病包括高血压、糖尿病、高脂血症、肥胖、高尿酸血症、慢性肾病、慢性阻塞性肺疾病、骨质疏松、冠心病、脂肪肝、骨关节炎、脑血管病、慢性心力衰竭、心房颤动、痛风、糖尿病肾病、甲状腺功能减退、阻塞性睡眠呼吸暂停、哮喘和慢性肝炎。

## 3. 数据结构

项目主线数据覆盖：

- 患者基本信息和疾病标签；
- 随访/就诊记录；
- 检验指标、数值、单位、参考范围和异常标记；
- 用药名称、类别、剂量、频次和依从性；
- 风险评分、风险等级和风险因素；
- 风险事件；
- 随访计划；
- 生活方式；
- 医嘱。

主键和关联键以 `patient_id`、`visit_id` 等匿名标识组织。统计问题优先采用去重患者口径；检验、用药、随访等记录数量采用事件/记录口径。一个患者可以同时属于多种疾病，因此各疾病患者数可以重叠。

## 4. 数据一致性与来源追踪

系统通过以下机制保持可追溯：

- 字段标准化和数据契约；
- 三元组合法性校验；
- 图谱边来源信息；
- 精确重复边检测；
- SQLite、图谱和当前指标快照的一致性核对；
- DataMate运行状态和报告；
- Open SQL trace和MCP调用trace；
- 发布清单中的文件哈希。

当前图谱边来源信息完整率为100%，精确重复边为0。该结论是数据工程一致性结果，不代表临床语义已经由医疗专家独立审核。

## 5. 模型来源

NPU增强路径使用[BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)完成文本embedding。模型权重不包含在本交付包中，由部署方按照上游模型卡、许可证和目标环境自行准备。

Open SQL可选通过[DeepSeek开放平台](https://platform.deepseek.com/)的OpenAI兼容接口调用`deepseek-chat`生成候选SQL。该功能默认关闭；显式启用时只向远程模型发送自然语言问题、白名单Schema元数据、字段枚举、疾病中英文映射和统计口径约束，不发送数据库记录、患者明细或本地密钥。候选SQL必须经过本地SQL Guard，模型无法直接访问或修改数据库。

## 6. 隐私与安全

- 数据不包含真实患者身份信息。
- 不应在截图、日志、trace或提交记录中加入真实姓名、证件、电话、住址或医疗机构内部标识。
- `.env`、API Key、代理凭据和服务器信息不得进入公开仓库。
- Open SQL只允许受控只读查询。
- 图谱和统计回答必须附带非诊断安全边界。

## 7. 使用限制

- 项目用于慢病随访数据处理、知识组织和辅助分析，不构成诊断或治疗建议。
- 合成数据中的疾病分布用于功能验证和统计分析演示，不能据此推断真实人群患病率。
- 统计结论以结构化数据库和知识图谱证据为依据，生成式模型负责意图理解与结果说明。
