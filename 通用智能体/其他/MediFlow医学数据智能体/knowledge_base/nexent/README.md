# Nexent 外部知识库

此目录保存 Nexent 文本知识库的接入说明和可重新导入的源文件。

`reconstructed_source_documents/` 包含依据当前 Nexent 服务端只读文档内容重建的 122 个文件。它们用于复建索引，不宣称为原始数据提供方的发行包；对外发布前应确认再分发权限。

## 当前运行态核对结果

- 旧显示名称：`ccf_medical_kb`；
- 并行索引显示名称：`ccf_medical_kb_1024_clean`；
- 服务端索引：由 Nexent 租户在导入时重新解析，不应把当前环境的索引编号当成永久编号；
- 并行索引使用 1024 维嵌入模型，当前已完成 507 个源分片且全部为 `COMPLETED`；目标环境重新导入后仍应核对文档数、分片数和检索结果；
- 知识图谱智能体和数据分析智能体已绑定 `knowledge_base_search`；
- 两个智能体当前使用 `accurate` 检索模式，已验证对知识库中存在的疾病文档能够返回原文；
- 旧索引的文档向量实际为 768 维，而服务端混合检索生成 1024 维查询向量，因此旧索引不能直接使用 `hybrid` 模式；
- 并行索引完成后，应优先验证 `hybrid` 和 `accurate` 两种模式，再决定目标环境的默认模式。

这不是 Agent 配置导出问题。若要恢复混合检索，需要使用与实际向量维度一致的嵌入模型重新建立索引并重新导入文档；这会生成新的 Nexent 知识库，不应在没有备份和确认的情况下删除当前索引。

## 为什么需要重新建立索引

知识库由 Nexent 服务端负责上传、切分、向量化和检索。Agent 导出文件只包含 Agent 配置、工具关系和 MCP 信息，不会自动携带知识库的全部原始文件。归档提供的重建源文件来自服务端只读文档内容，便于复建，但仍需按目标环境的数据授权规则使用。

在目标环境使用时，请上传 `reconstructed_source_documents/` 中的文件，创建知识库并选择 1024 维嵌入模型，然后把新知识库绑定到需要文本检索的智能体。导入 Agent 后还要将 `knowledge_base_search` 参数中的 `index_names` 改为目标环境生成的索引标识。
