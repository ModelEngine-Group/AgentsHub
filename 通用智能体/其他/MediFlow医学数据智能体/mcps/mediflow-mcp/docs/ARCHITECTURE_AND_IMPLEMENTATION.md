# 架构与实现说明

MediFlow 将三个 Nexent 智能体的业务能力集中到一个可复用的 MCP 服务中。Nexent 负责对话和工具编排，DataMate 负责数据集与算子运行，MediFlow MCP 负责医学处理逻辑和数据库访问。

## 总体结构

```text
Nexent 智能体
  → MCP 工具层
  → 数据处理 / 医学抽取 / 数据分析服务
  → DataMate 自定义算子、知识图谱数据库、分析数据库
  → 文字、表格、图表和来源信息
```

Nexent 原生知识库是可选的旁路能力：它负责检索疾病背景原文，适合回答“是什么、为什么、依据在哪里”；SQLite 数据库负责实体关系、数量、排序和统计查询。两者在服务结果中分开管理。

## 模块职责

| 模块 | 作用 |
| --- | --- |
| `clients/` | 适配 Nexent、DataMate 等外部平台 |
| `core/` | 医学实体、关系、术语、质量和查询逻辑 |
| `operators/` | DataMate 可执行的单步处理算子 |
| `mcp_server/` | MCP 工具注册和三个能力域的流程编排 |
| `kg/` | 知识图谱库和分析库的离线构建 |
| `task3/` | 自然语言分析、只读查询、图表和报告数据 |
| `data/` | 数据库展开位置和本地输入位置 |
| `docs/` | 配置和架构参考 |

## 数据处理链路

1. 数据处理智能体通过 MCP 识别 DataMate 数据集和文件格式；
2. MCP 为 TXT、CSV、JSON、JSONL 和 PDF 选择相应处理流程；
3. DataMate 执行格式整理、术语规范化和质量检查算子；
4. 结果保留源格式、文件标识和处理证据，供后续医学抽取使用。

## 知识图谱链路

1. MCP 将不同格式资料统一转换为可抽取记录；
2. 本地词典、规则和可选模型共同识别实体、关系和三元组；
3. 结果写入知识图谱数据库，并登记文件、数据集和原文来源；
4. 分析数据库从图谱数据派生统计表，供自然语言查询使用。

## 数据分析链路

1. 数据分析服务从自然语言问题识别疾病、关系、筛选和统计意图；
2. 常见医学事实优先使用稳定查询规划，复杂统计问题使用受限查询规划；
3. 查询只读取分析数据库，结果与 SQL、来源、耗时和分析编号关联；
4. 服务根据字段和意图生成表格、图表及可下载结果。

## 运行边界

- Nexent、DataMate 和外部模型服务由目标环境提供；
- 运行数据库由归档根目录的 `prepare_runtime_assets.py` 展开；
- 可选分析前端不属于本 MCP 归档包，MCP 只报告目标环境配置的访问地址；
- 公开发布时只使用无密钥配置模板，实际密码和 Token 保存在运行环境。
