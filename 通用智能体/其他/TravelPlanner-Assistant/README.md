# 旅游规划助手（TravelPlanner-Assistant）

基于 **Nexent v2.8.3** 构建的中文旅游规划智能体。输入出发地、目的地、出行时间、天数、人数、预算和偏好，输出可直接执行的逐日行程、逐项预算算式、行前准备清单和需要核实的信息；也可以审计用户已有的行程，找出时间、路线、预算和预约上的问题。门票、开放时间、预约政策等会变化的信息通过 `tavily_search` 检索核实，并按三级置信度标注来源；天气、交通班次、实时路况等实时信息明确说明服务边界，不做编造。

> 本目录中的 `agent.json` 来自 Nexent 平台导出，并在发布前完成脱敏：已清空租户标识与工具密钥，`model_ids` 为导出环境的本地数据库 ID，导入后需要重新选择模型。

## 功能

- **需求采集**：提取出发地、目的地、日期、天数、人数、预算、偏好和特殊需求；关键信息缺失时先追问，一次最多 3 个问题。
- **行程编排**：按天拆解为上午/下午/晚间，写明景点、建议时长、交通方式和大致耗时，优先串联邻近景点，单日景点不超过 4 个（老人/儿童同行时不超过 3 个并注明休息点）。
- **预算核算**：分项列出往返交通、住宿、餐饮、门票、市内交通和备用金，每项先写算式再写结果，逐项相加得出合计与余额，估算项明确标注。预算不足时给出 2–3 个带金额的替代方案，而不是笼统建议"压缩"。
- **信息核实与置信度**：门票、开放时间、预约政策通过搜索工具核实，并按【已核实·双源】/【单一来源】/【未核实】三级标注；来源优先级为官方渠道 > 官方票务平台 > 第三方平台，冲突时以官方为准。
- **信息时效**：每次完整规划末尾输出检索日期和建议复核时间，明确哪些信息会过期。
- **失败降级**：检索工具不可用时，按"告知无法联网 → 给出官方渠道 → 继续给不依赖实时数据的方案"三步处理，不中断对话、不编造数字。
- **行程审计**：用户贴出已有行程时，按时间强度、路线折返、预算、预约证件、信息可靠性五项检查，输出按严重程度排序的问题清单和修正建议。
- **多轮调整**：保留未变更条件，说明调整项并重新核对预算合计。

## 导入与配置

1. 在目标环境部署或登录 Nexent，并获得智能体开发权限。
2. 进入 **智能体开发 → 导入**，选择本目录中的 `agent.json`。
3. 按导入向导选择目标环境中可用的模型（导出文件中的 `model_ids` 是导出机器的本地 ID，不能直接复用）。
4. 打开导入的智能体，进入 **工具管理 → `tavily_search` → 配置**。导出文件中的 `tavily_api_key` 已置空；若目标环境的检索工具没有内置可用凭据，请填入自己申请的 Tavily API Key，否则无法联网核实票价与开放时间。
5. 发布前测试简单问答、门票检索、行程规划和行程审计，确认无误后再发布。

**安全提醒：** 不要把 API Key、租户密码、登录令牌等信息提交到仓库。若重新导出已配置的智能体，请再次检查工具参数中的密钥。

## 使用示例与预期输出

**示例 1：完整规划**

输入：`两个人从重庆出发去成都玩4天，预算5000，喜欢美食和古镇`

预期：输出需求确认、逐日行程表、逐项预算表（含算式、合计与余额）、行前准备清单、需要核实的信息和信息时效；门票类信息应检索并按置信度标注。

**示例 2：信息不足**

输入：`帮我规划旅游`

预期：不直接编造行程，先追问出发地/目的地、天数与时间、预算与人数，一次不超过 3 个问题。

**示例 3：实时信息边界**

输入：`成都国庆期间天气怎么样？`

预期：说明天气不在服务范围，不调用检索工具，不给具体温度数字，引导查询中国天气网或天气 App。

**示例 4：预算调整**

输入：`总预算改成1200元，其他条件不变，请重新规划并说明变化`

预期：保留目的地、天数、人数等条件，给出带金额的替代方案（改交通/改住宿/换免费景点），重新逐项列预算算式并核对合计与余额。

**示例 5：门票检索与置信度**

输入：`成都欢乐谷门票多少钱？`

预期：调用 `tavily_search`，区分官方票价与第三方参考价，用【已核实·双源】/【单一来源】/【未核实】标注，并说明官网未公示的散客标准价。

**示例 6：老人同行**

输入：`带父母去西安3天，老人腿脚不便，行程轻松一点`

预期：识别出发地、预算、时间等缺失信息并追问；说明老人同行时的节奏控制与休息安排原则。

**示例 7：行程审计**

输入：`帮我看看这个行程行不行：第1天重庆到成都，下午宽窄巷子、人民公园、武侯祠、锦里，第2天都江堰加青城山，第3天黄龙溪，第4天返程，两人预算1200`

预期：输出结论 + 按高/中/低排序的问题清单（时间超载、路线折返、预算缺口、预约缺口）+ 预算重算 + 修正建议 + 修正后关键变化。

## 数据时效与维护

旅行信息的时效性强，本智能体采用"运行时检索 + 标注时效"的方式，不内置易过期的门票数据库。

| 信息类型 | 建议复核时间 | 说明 |
| --- | --- | --- |
| 门票价格、开放时间、预约政策 | 出发前 7 天，节假日提前 14 天 | 以景区官网/官方公众号为准 |
| 高铁/动车班次与票价 | 出发前 1–3 天 | 以 12306 为准 |
| 天气、实时路况 | 出发前 1–7 天 | 不在智能体服务范围，引导官方渠道 |
| 酒店价格 | 预订时确认 | 旺季与节假日波动大 |

维护建议：若后续为智能体补充本地知识库或参考数据，请为每份数据标注 `last_updated`（最后更新日期）、`staleness_days`（有效期）和来源；过期数据应刷新或标注，不得当作实时信息使用。

## 设计说明

提示词按三层组织，便于维护和审查：

1. **核心规则**：信息采集、置信度分级、来源优先级、降级路径、预算核算规则、行程审计方法。
2. **输出模板**：完整规划的五段式结构 + 信息时效块；审计的问题清单结构。
3. **示例**：7 个场景覆盖完整规划、追问、实时信息边界、预算调整、门票检索、老人同行和行程审计，确保示例中的交付物与规则声明一致。

设计取舍：

- 不在仓库内置门票价格数据，避免数据过期误导；改为检索 + 置信度 + 时效声明。
- 不接入积分/里程/航司联盟等专业旅行黑客能力，保持"通用旅游规划"定位，降低使用门槛。
- 工具失败时优先保证回答完整性和诚实性，而不是中断对话。
- 开启 `enable_protocol_repair_retry`，并在提示词中禁止在正文输出工具调用标记，避免模型把原生工具调用格式泄漏为正文（已在敦煌多轮场景回归验证）。

## 能力边界

- 天气、交通班次、实时路况不在服务范围内，仅提供官方查询渠道，不给具体数字。
- 票价、开放时间、预约政策以景区和铁路官方渠道为准；检索结果可能过期，出行前需再次核实。
- 不代订票务、酒店，不处理支付信息，不索要密码或验证码。
- 不推荐具体旅行社，不承诺价格有效性。
- 搜索结果来自公开网页，可能存在不准确或过期内容；智能体会按三级置信度标注，但不保证第三方信息准确。
