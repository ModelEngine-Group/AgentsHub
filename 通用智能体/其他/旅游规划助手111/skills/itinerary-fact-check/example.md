# 示例与常见错误对照

## 示例一：景点最后入场时间

事实：东京某美术馆最后入场时间。
- 输入字段：`opening_hours: 10:00-17:00`，`last_admission: 16:30`，`checked_at: 2026-06-01`，目标日 2026-12-20。
- 判定：`checked_at` 早于目标日，降级为「常规规则可用于初稿」。
- 输出行：

| 事实 | 状态 | 来源 | 适用日期 | 核验日期 | 若不成立的影响与备选 |
|---|---|---|---|---|---|
| 最后入场 16:30（非 17:00 闭馆） | 常规规则可用于初稿 | 官方页面 last_admission 字段 | 2026-12-20（未核目标日） | 2026-06-01 | 若当日提前截止，需改约 15:30 前入场；备选相邻展馆当日开放 |

## 示例二：票价淡旺季

- 输入：`price: {amount: 1200, currency: JPY, unit: 成人/次, category: 常设展, condition: 旺季}`
- 正确：标注为旺季成人常设展票，不得用于非旺季日期。
- 错误：把 1200 直接作为全年票价写入行程。

## 示例三：预约与余量

- `reservation: 需提前线上预约` 仅说明规则，不代表已订票。
- 余量必须在目标日当日或临近日查询，否则写「待核验」并附预约入口与备选场馆。

## 示例四：交通末班

- 事实：某线路末班车时间。
- 来源应选运营方（如 12306 / 地铁官方），不得用攻略帖。
- 未核目标日 → 「常规规则可用于初稿」；发现当日临时调整公告 → 「已核实」并注明公告发布日期。

## 常见错误对照

| 错误做法 | 正确做法 |
|---|---|
| 把闭馆时间当最后入场 | 使用 `last_admission` |
| 混用淡旺季价格 | 标明 category 与 condition |
| 把预约规则当已订票 | 标注规则 + 余量当日查 |
| 用攻略帖支撑“已核实” | 只用官方来源支撑已核实 |
| 忽略 checked_at 时效 | 早于目标日即降级 |
| 多源冲突直接采信任一 | 比对发布日期与适用范围，无法判定给联系方式 |
