# 行程信息核验助手

目标：把行程中的易变字段标成可追溯的证据状态，不臆造结论。任何一条事实都必须落在四种证据状态之一。

## 使用说明

### 1. 拆解事实

从行程中提取需要核验的字段，逐条独立成行：景点开放/预约/票价、交通班次与末班、天气与预警、签证入境、路线估时。

### 2. 按来源选源（§4.1）

- 景点开放/预约/票价 → 条目内 `stable_source_urls` 与官方票务
- 交通班次/末班 → 铁路/航司/地铁/机场运营方（中国铁路 12306）
- 天气与预警 → 中央气象台（中国）/ 日本气象厅（日本）
- 签证入境 → 国家移民管理局、日本外务省、使领馆
- 路线估时 → 地图工具或场馆导览

优先采用目标日期内可用的官方来源；非官方来源（攻略、社区）只能作为线索，不能作为「已核实」依据。

### 3. 判定证据状态（§4.2）

每条事实必须且只能落在以下一种：

- **已核实**：写「适用日期 + 核验日期 + 来源链接」。
- **常规规则可用于初稿**：有稳定规则但未核目标日，需注明"未核目标日"。
- **估算**：写区间、计算假设、未计入项。
- **待核验**：给查询入口 + 需核验字段 + 备选方案。

### 4. 读取动态字段（§8 POI）

- `opening_hours` 是开放区间，`last_admission` 才是最后入院；禁止把闭馆时间当最晚入场。
- `price` 为页面公示票种，须含 currency/unit/category/condition，不得混用淡旺季价格。
- `reservation` 描述的是规则，不代表已订票；余量必须当日查。
- `checked_at` 早于目标日时，一律降级为「常规规则可用于初稿」。

### 5. 处理冲突

- 目标日期内的临时公告优先于常规规则。
- 多源冲突时比对发布日期与适用范围；无法判定则给出联系运营方的建议。

### 6. 输出

按固定表格输出，若含备选方案在最后列说明。字段缺失时标「待核验」并给出查询入口，不得留空或臆补。

| 事实 | 状态 | 来源 | 适用日期 | 核验日期 | 若不成立的影响与备选 |
|---|---|---|---|---|---|
