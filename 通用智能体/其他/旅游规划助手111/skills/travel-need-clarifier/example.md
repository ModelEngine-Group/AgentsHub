# 示例

## 场景
会话当前时间：2026-11-22。用户：「下周末想带娃去上海玩两天，预算最多 3000 含高铁，最好住地铁口，外滩必须去，城隍庙可选。」

## 处理要点
- 日期：「下周末」→ 2026-11-28（周六）、2026-11-29（周日）。
- 人员：「带娃」但缺年龄、人数 → 列入待确认（影响步行上限与推车）。
- 预算：「最多 3000 含高铁」按用户原话视为硬上限，不得改写成「约 3000」。
- 偏好：「最好住地铁口」为软偏好，不追问；「外滩必须去」为硬必去；「城隍庙可选」记入可选。
- 待确认按可行性影响排序：人数与儿童年龄 > 出发城市（是否已定）> 返程时间。

## 期望输出

```
【需求摘要】未定→上海（可换？）｜2026-11-28 至 2026-11-29｜人数待确认，含儿童｜硬上限 3000 元含高铁｜必去：外滩；可选：城隍庙｜无已订锚点
【日期风险】
  2026-11-28 周末 无特殊标记
  2026-11-29 周末 无特殊标记
【待确认】
  1. 出行人数与儿童年龄（决定步行上限、是否需要推车与儿童票）
  2. 出发城市及是否已订高铁票（决定 3000 硬预算的余量）
  3. 返程最晚时间（影响 29 日可安排内容）
【暂定假设】
  出发地为邻近华东城市；住宿预算 ≤ 600 元/晚且优先地铁口；节奏为悠闲（每日 1 个主景点）
```

## 反例（应避免）
- 把「最多 3000」写成「预算约 3000」。
- 因「最好住地铁口」缺失具体区域而追加提问。
- 一次性列出 5 条以上待确认。
- 索取护照号码或证件照片。
