# 旅游规划助手

根据出发地、目的地、出行时间、同行人和预算生成中文旅游计划，提供每日路线、费用核算、预约清单及雨天备选。作者：Zyohk。

## 同目录配置说明

本目录保留两个独立导出的智能体，请按需选择一个导入并配置可用的大语言模型：

- `agent.json`：本说明下文介绍的 Zyohk 版本，附有 `evaluation/` 中的八场景评估资料。
- `旅游规划助手.json`：上游已收录的旅游规划助手，支持按天安排景点与活动顺序、提供交通住宿餐饮及预算建议、在信息不足时询问必要问题，并按偏好调整行程节奏。可直接在 Nexent 中导入该文件后选择模型。

两份配置均未接入实时联网查询，天气、开放时间、票价、交通班次与费用需向官方渠道核实。下述模型参数和 8/8 评估成绩仅对应 `agent.json`，不代表另一份配置也完成了相同评估。

## 功能

- 需求不完整时先用不超过三个合并问题澄清；信息充分时直接给出方案。
- 按相邻区域安排每日活动，兼顾交通、用餐、休息和返程缓冲。
- 适配亲子、长者和低体力出行；识别无法同时满足的预算或时间条件。
- 按全团口径逐项计算交通、住宿、餐饮、门票、当地交通及机动金。
- 明确区分估算和实时信息，不虚构联网查询、预订或付款。

## 导入与配置

1. 在 Nexent 的“智能体开发 → 导入”中上传本目录的 `agent.json`。
2. 配置可用的对话模型。原环境使用 `deepseek-flash`；导出中的模型 ID `2` 和智能体 ID `4` 属于源环境，不要求目标环境具有相同 ID。按导入提示匹配模型；导入后检查绑定与参数。
3. 原配置最大步数为 3，输出预算为 16384，温度为 0.2，使用 DeepSeek 兼容的 `thinking: {"type": "disabled"}` 参数。更换供应商时，应检查并移除不支持的参数；新配置需重新评估。
4. 检查提示词和会话引导，调试通过后发布，再进入“开始问答”选用。

在 Nexent v2.7.0 中完成开发与评估。无需知识库、自定义 Skill、MCP 或额外服务；不包含模型密钥。提交版本仅移除了源租户标识，提示词和运行参数保留自用户提供的平台导出。

## 使用示例

> 从上海出发，两个人去杭州玩3天，总预算3000元，包含往返交通。喜欢人文和美食，请提供每日路线、预算和雨天备选，价格可以估算。

预期输出包含需求与假设、3天2晚行程、交通与休息安排、全团费用合计及余额、预约核实清单和雨天替代方案。

## 评估与复现

2026-11-01 在 Nexent 完成 8 个独立案例评估，规划模型 `deepseek-flash`，评审模型 `deepseek-v4-pro`。预设通过阈值 **0.8**，结果 **8/8 通过，平均分 0.95**。

| 场景 | 分数 |
| --- | --- |
| 完整行程与预算 | 1.0 |
| 亲子长者体力约束 | 0.8 |
| 信息不足时澄清 | 0.8 |
| 不可能预算识别 | 1.0 |
| 实时信息真实性 | 1.0 |
| 给定时段与返程约束 | 1.0 |
| 预算计算与已付费用 | 1.0 |
| 权限与餐饮安全 | 1.0 |

`evaluation/cases.json` 提供输入与验收条件，`evaluation/evaluator.json` 提供评审提示词和阈值，`evaluation/results.json` 保存实际输出、分数和评审理由。复现时在“智能体评估”创建评估集，将 query 写入 inputs.query、expected 写入 label.answer，建立并发布 LLM 评估器、选择目标环境的评审模型后运行。结果受模型版本和生成随机性影响。

评审指出：长者场景的离店日午休地点应更明确；信息不足案例漏问出发地。结果仅代表这八个场景，不代表全部旅行建议均准确。

## 能力边界

当前未配置联网查询，不能核实天气、余票、票价、临时开放或入境规定；请通过相关官方渠道确认。费用与通行时间为估算，不代订酒店、不付款，也不需要密码、验证码或完整证件号码。饮食过敏需向餐厅确认成分和交叉接触风险，无法保证绝对无过敏原。
