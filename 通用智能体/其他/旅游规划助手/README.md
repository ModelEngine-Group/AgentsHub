# 旅游规划助手

基于 Nexent 的中文行程规划智能体。它把预算、时间、路线和同行者需求当作约束，支持单城市与多城市旅行，并提供雨天替代安排。与本仓库已有的 TravelPlanner-Agent 相比，本助手重点检查跨城衔接、每天时段冲突、预算加总及超支调整。

## 功能

- 收集目的地、日期、人数、预算、兴趣和特殊需求；缺少关键条件时集中追问。
- 按天安排上午、下午、晚上活动，预留交通、餐饮、休息及返程时间。
- 列出分项预算、总计和人均费用；超支时给出调整方案。
- 为天气敏感活动准备备选方案；照顾儿童、老人和无障碍需求。
- 区分估算与实时信息。需要开放时间、票价或预约信息时，要求核实官方渠道。

## 导入和配置

1. 在 Nexent 中取得智能体开发权限，配置可用的大语言模型。
2. 进入“智能体开发”并导入 `agent.json`，按平台提示绑定目标环境中的模型。
3. 若配置了联网搜索工具，先测试工具连通性。未配置搜索时，助手会标明实时信息待核实。
4. 使用下面的样例测试，再发布智能体。

`prompt.md` 与平台导出的角色、使用要求、示例一致；`agent.json` 是供 Nexent 导入的正式配置。导出文件已移除本地租户 ID 和作者邮箱，不含模型 API Key。导入其他环境后需重新绑定可用模型。

## 本地验证

在 Nexent v2.5.0 中创建并发布 `v1.0.1`，使用 DeepSeek Flash 测试。模型连通性检查通过。输入“两位成人从上海出发，去杭州玩两天，预算总共2000元，偏好慢节奏。请给行程和预算，未提供日期。”后，智能体返回两天行程、预算表、雨天备选及待核实清单。分项合计为 1572 元，人均 786 元，低于 2000 元预算。多轮将预算改为 1200 元后，主方案调整为 1122 元、人均 561 元。根据复算发现的备选方案加总偏差，`v1.0.1` 增加了各方案逐项复算约束。该环境未配置搜索工具，实时价格和开放信息仅作估算并标为待核实。

## 测试样例

| 场景 | 输入示例 | 检查点 |
| --- | --- | --- |
| 信息不足 | “帮我安排旅行。” | 集中询问目的地及日期或天数。 |
| 预算约束 | “两人从重庆去成都玩两天一晚，总预算 1500 元，偏好美食。” | 两天行程、分项费用和合计一致；超支时调整。 |
| 多城市 | “从上海出发，杭州和苏州共玩四天，同行有老人，节奏慢。” | 城际移动先安排；每日路线留足休息。 |
| 实时信息 | “下周故宫门票和开放时间是多少？” | 有搜索时引用官方来源；无搜索时标为待核实。 |
| 多轮修改 | 在预算样例后说“预算改为 1200 元，其他不变。” | 保留目的地、人数、天数，重算费用。 |

## 使用边界

价格和时间随日期变化，预算属于估算；正式出行前应在官方渠道核实班次、票务、开放时间及预约规则。助手不会代用户预订或付款。
