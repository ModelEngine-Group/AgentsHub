# 驰行 · 自驾公路旅行规划助手（RoadTrip Planner）

基于 **Nexent v2.8.3** 构建的中文自驾游规划智能体。它不写泛泛的"旅游攻略"，而是产出一份**司机可以直接照着开的路线单**：里程算得清、时间排得下、油电供得上、费用对得齐。

输入出发地、路线方向、天数、同行人数与驾驶员人数、车型与能源类型、预算和偏好，即可得到逐日路线单、车辆与补给计划、可对账的费用明细、待核实清单和行前安全检查。

> 本目录中的 `agent.json` 由 Nexent 平台导出后脱敏：`deepseek_api_key` 已置空，`tenant_id` 与作者信息已清理。导入后需自行配置模型与搜索工具 Key。

## 与仓库内已有旅游智能体的区别

仓库中已有 `TravelPlanner-Agent`、`TravelPlanCompanion-行程管家`、`Lushu-TravelPlanner`、`BudgetTravelPlanner-Agent` 等通用旅游规划智能体，它们的默认假设是"公共交通 + 城市游"。

本智能体把约束换成了自驾场景，解决的是另一类问题：

| 维度 | 通用旅游助手 | 本智能体 |
| --- | --- | --- |
| 移动方式 | 地铁、打车、高铁 | 自驾，需考虑道路类型、里程、停车 |
| 时间约束 | 景点开放时间与通勤 | 单日驾驶时长、休息轮换、夜路禁令 |
| 费用核心 | 大交通 + 住宿 + 门票 | 油费/电费 + 过路费 + 停车费 + 住宿 + 门票 |
| 特有风险 | 赶不上班次 | 疲劳驾驶、续航焦虑、封路、限行、高原与山路 |
| 补给规划 | 不涉及 | 加油/快充节点、SOC 余量、服务区间隔 |

## 功能

- **需求一次性问齐**：从输入中提取出发地、路线方向、日期天数、人数与驾驶员人数、车辆与能源类型、预算口径、偏好与限制；关键项缺失时用一条消息集中追问，不做挤牙膏式反复提问。
- **路线编排带硬约束**：按高速/国省道/山路分级设置单日里程上限（高速 ≤450km、国省道 ≤300km、连续山路 ≤250km），单日净驾驶 ≤6 小时，单人驾驶进一步收紧到 5 小时/400km。
- **休息与轮换**：每 2 小时或 150km 安排休息，多驾驶员每 2 小时轮换；明确禁止连续驾驶 4 小时以上、夜间山路、雨雪大雾赶路。
- **车辆与补给计划**：燃油车按路况估算油耗并保留 ≥100km 续航余量；纯电车按 CLTC 7 折、低温高原再打 8 折规划快充，保持到达 SOC ≥15%；插混给出保电策略；租车标注异地还车费用。
- **特殊路况提示**：高原动力衰减与氧气药品、山区长下坡与防滑链、沙漠戈壁补给与信号盲区、冰雪封路与轮胎要求。
- **费用逐项列算式**：油费 = 里程 ÷ 100 × 油耗 × 油价；电费区分家充/公共桩/高速桩；过路费按一类客车费率估算。合计必须等于各项之和，每日小计与明细表相互对账，备用金单列。
- **超支三档降本**：合计超预算时给出「A 住宿降档 / B 路线缩短或减少付费景点 / C 换更省油车型、拼车或调整日期」三档方案，注明可省金额与新合计。
- **实时信息核实**：油价电价、限行、封路、景区预约、天气预警、充电桩状态通过 `deepseek_search` 查询，标注来源与查询日期；检索无果或来源冲突时写"待核实"并给官方渠道，禁止编造。
- **每天一条 Plan B**：为封路、塌方、景区临时关闭准备替代路线或替代住宿点。
- **多轮增量修订**：改天数、预算或车型时，只输出变更路段与费用变化，并重新核算合计，不整篇重抄。

## 导入与配置

1. 在目标环境部署或登录 Nexent，获得智能体开发权限。
2. **模型**：进入模型配置页，添加 OpenAI 兼容的对话模型（如 URL `https://api.deepseek.com`、模型名 `deepseek-chat`）并验证连通性。
3. **导入智能体**：进入智能体开发 → 导入，选择本目录的 `agent.json`；按提示把 `model_ids` 映射到步骤 2 中配置的模型。
4. **配置工具密钥**：打开导入后的智能体 → 工具管理 → `deepseek_search` → 配置，填入你自己申请的 DeepSeek API Key（导出文件中的 `deepseek_api_key` 为空，不填则无法联网核实限行、封路、油价与充电桩信息）。
5. **测试**：执行下方用例 1 与用例 2，确认模型应答、工具调用与费用对账均正常后发布。

> 文件说明：`agent.json` 由 Nexent 平台导出后做了三处处理——清空 `deepseek_api_key`、清空 `tenant_id` 与作者信息、移除运行时参数 `language`。最后一项是必要的：`language` 会在导出时写入 `params`，导入时会报 `Parameter language ... cannot be found`，导致导出的文件无法再次导入。如你在自己的环境重新导出，请一并删除该项。

> 安全提醒：不要把 API Key、租户密码、会话令牌提交到仓库。若重新导出已配置的智能体，请再次检查工具参数中的密钥是否已清空。

## 使用示例

**用例 1：单司机川西环线（不依赖工具）**

输入：`两个人从成都出发自驾川西小环线 5 天，一台燃油 SUV，只有我一个司机，总预算 6000 元。请直接给路线单和费用表。`

预期：输出「假设说明 → 路线总览 → 逐日路线单 → 车辆与补给计划 → 费用明细表 → 待核实清单 → 行前检查」。单日里程按单司机标准控制在 5 小时/400km 内，每 2 小时标注休息点；油费与过路费给出完整算式，合计与每日小计可对上；若超预算给出三档降本方案。

**用例 2：纯电车补能与节假日排队**

输入：`开纯电车从上海到杭州千岛湖 3 天，帮我规划快充节点，担心节假日排队，注明充电站信息来源。`

预期：触发 `deepseek_search` 查询沿途服务区快充与景区周边充电站，标注来源与查询日期；按 CLTC 7 折估算续航，保证到达充电点 SOC ≥15%，给出备选充电站与排队风险提示。

**用例 3：实时信息与来源标注**

输入：`查一下这条路线沿途本周的高速封路和城市限行信息，注明来源。`

预期：调用 `deepseek_search`，按路段列出施工/封路与限行规则，逐条标注来源与查询日期；对第三方转载与官方口径不一致处主动指出差异；末尾给出官方核实渠道。

**用例 4：多轮增量修订**

在同一会话中继续输入：`预算改成 4500 元，其他条件不变，帮我重新规划并说明变化`

预期：保留出发地、路线、人数与驾驶员条件，只输出被改动的路段、住宿调整与新费用合计，并说明与上一版的差异。

> 用例 1-3 为提示词行为约定与工具调用路径说明，建议导入后按上述输入各回归一次并记录实际输出。

## 设计取舍

- **先算能不能开，再谈好不好玩**：自驾行程最常见的失败不是景点选错，而是单日里程排太满、司机疲劳、电车找不到桩。本智能体把里程、时长、续航作为第一约束，景点在此之下取舍。
- **只做自驾**：不试图覆盖高铁与跟团场景，避免在一套模板里同时兼容两种完全不同的约束体系。
- **油电分开算**：燃油与纯电的成本结构、补给逻辑、风险点差异很大，统一按"交通费"估算会失真，因此要求分别给出算式与节点。
- **宁标"待核实"也不猜**：限行、封路、油价、充电桩状态变化快，编造一个数字的代价远高于让用户多点一次官方链接。
- **费用当成约束而不是总结**：要求三处金额（路线单参考费用、每日小计、明细表合计）互相咬合，超支必须给出可选的降本方案，而不是只报一个"大概多少钱"。

## 局限与说明

- 未接入地图路径规划、实时路况与气象专用 API；行驶耗时、里程与油耗为基于道路类型的经验性估算，不保证实时准确。
- 充电桩与加油站信息来自公开网页检索，可能与现场实际情况存在差异（占用、故障、排队），出行前请以运营方 App 或现场信息为准。
- 景区预约、限行与封路政策具有时效性和地域差异，回答中的来源与查询日期需由用户自行复核。
- 不执行加油、充电、酒店预订、门票购买、支付等真实交易。
- 联网检索依赖可用的 DeepSeek 服务额度，可能产生 API 成本。
- 本智能体输出为辅助规划建议，实际行车请遵守交通法规，以现场交通标志和交管部门发布的信息为准。
