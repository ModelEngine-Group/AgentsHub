# 示例二：把积分结果写错成「看起来像」的函数

## 输入

> ∫ dx/(1 + x²) = ln(1 + x²) + C 吧？分母是 1+x²，取对数正好对上。

## 工具调用

```
compare_expressions(expr_a="ln(1+x^2)", expr_b="arctan(x)")
check_derivative(expr="ln(1+x^2)", point="1")
```

## 工具返回（节选）

```json
{
  "verdict": "different",
  "equivalent": false,
  "max_relative_difference": 1.764918474,
  "reason": "存在采样点差异超出容差，两者不相等",
  "first_mismatch": {"x": -2.3, "a": 1.838961071, "b": -1.160668986}
}
```

```json
{
  "order": 1,
  "point": 1.0,
  "value": 1.0,
  "confidence": "high",
  "summary": "f^(1)(1.0) ≈ 1.0，估计误差 4.166661e-08"
}
```

## 助手回复（直接订正，因为这是单点错误）

不对，这里有个符号/函数混淆。两个线索：

1. **验算比对**：`ln(1 + x²)` 与 `arctan x` 在采样点上差异很大（最大相对差约 1.76），不是同一个函数。
2. **求导反查**：`ln(1 + x²)` 在 x = 1 处的导数是 **1.0**，而被积函数 `1/(1 + x²)` 在 x = 1 处的值是 **0.5**。原函数的导数必须等于被积函数，这里对不上，说明答案错。

正确结果是 `arctan x + C`。你可能是被「1 + x²」这个形状带偏了：分母 1 + x² 对应的是反正切，而 ln 对应的是分母为一次式的情形（∫dx/x = ln|x|）。

对应讲义条目：HM-04-01（基本积分表）、HM-04-04（有理函数积分）。

## 为什么这样处理

学生给的是一个完整答案，属于「订正错解」而非「求解」，所以直接给结论更高效。但结论必须给出**可自行复核的依据**：导数反查是学生自己就能做的检验，比教师断言「你错了」有用得多。

这也演示了 `compare_expressions` 的定位：它只回答「是否等价」，不解释原因；原因要由答疑者补上。
