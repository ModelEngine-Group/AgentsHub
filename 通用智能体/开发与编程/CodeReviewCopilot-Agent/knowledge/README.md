# 知识库导入说明

本目录是「代码审查助手」的知识库源文件，**三份文档均为本作品原创编写**，不引用任何第三方规范原文，不含真实凭据、真实业务代码或个人信息。

## 1. 三份文档各自的作用

| 文档 | 作用 | 缺失后会出现什么 |
| --- | --- | --- |
| `编码规范_v1.2.md` | 给每条规则提供可引用的条款号 | 「依据」列全部变成「未命中团队规范」，报告退化为通用建议 |
| `历史评审结论_节选.md` | 给同类问题提供既往判定，稳定严重度 | 同样的 SQL 拼接有时报 blocker、有时报 major |
| `豁免清单.md` | 过滤测试目录和示例代码产生的误报 | `eval/samples/tests/test_login.py` 的两条候选会被误报为问题 |

三者缺一，报告的「依据」列或误报率就会变化。**README 里的消融对照表就是靠这个差异做证据的**，不是靠主观描述。

## 2. 导入步骤

1. 左侧菜单「智能体开发」→「**知识库配置**」（`/knowledges`），点新建，名称填 `code-review-standards`，向量模型选环境已配的 `text-embedding-v4`（1024 维），点「创建并进入」。
2. 在「上传文档，构建知识库」页上传本目录下**三份** `.md`：`编码规范_v1.2.md`、`历史评审结论_节选.md`、`豁免清单.md`，等向量化完成。**不要上传本 `README.md`**，那是说明文档，混进去会污染检索。
3. **分块参数不用在这里配**：平台按 embedding 模型的默认块大小自动切分（默认期望 1024 / 最大 1536 字符），界面上没有「按 `##` 分块」的设置项。`search_mode = hybrid`、`top_k = 3`、`rerank = false` 是 `knowledge_base_search` 的**工具参数**，在组装智能体时的「工具配置」弹窗里设。
4. **不用手抄 `index_names`**：工具配置弹窗里直接勾选 `code-review-standards` 这个知识库，平台会把它的 `index_name` 自动填进参数。导出文件里的 `index_names` 是本机 ID，别人导入后必须重新勾选，否则检索恒为空。

## 3. 召回自检（智能体组装后必做）

平台没有独立的知识库检索调试窗口。这四条要在**智能体调试窗口**里跑（导入 `agent.json`、给 `knowledge_base_search` 绑好知识库之后），观察工具返回；也可以在正式对话里直接问，看回答是否引用了对应条款：

| # | 查询词 | 期望命中 |
| --- | --- | --- |
| 1 | `生产密钥硬编码怎么处理` | 《编码规范 v1.2》§4.1 |
| 2 | `SQL 字符串拼接 历史评审 判定` | 《历史评审结论》R-2026-07 |
| 3 | `测试文件里的 print 要不要上报` | 《豁免清单》§2.1 |
| 4 | `成都欢乐谷门票多少钱` | 无相关条款；若返回了编码规范内容，说明检索阈值或提示词没兜住 |

第 4 条是**负样本**。它存在的意义是防止智能体拿知识库内容去回答无关问题——提示词里已经禁止编造依据，知识库这边也要确认不会硬凑。

## 5. 目录里为什么有 `eval/samples`

`../eval/samples/` 是五个带已知缺陷的评审样例，用来复现验收表里的数字。它们**不进知识库**——把样例代码混进规范文档会污染检索，让「依据」列命中代码片段而不是条款。
