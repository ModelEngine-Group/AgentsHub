# 团队 Python 编码规范 v1.2

适用范围：本团队维护的 Python 服务端代码。版本 v1.2，2026-10 修订。条款号在代码审查报告里直接引用，格式为「《编码规范 v1.2》§x.y」。

## §1.3 函数默认参数不得使用可变对象

函数签名里的默认值在定义时求值一次，所有调用共享同一个对象。`def f(items=[])` 会让上一次调用写入的数据留到下一次。需要空容器时写 `items=None`，在函数体内 `items = [] if items is None else items`。对应审查规则 CR-006（minor）。

## §2.3 异常必须被显式处理

禁止裸 `except:`，也禁止 `except ...: pass` 这类静默吞异常。至少要捕获具体异常类型，并写入日志或向上抛出；确实要忽略的，必须在同一行写明原因并加 `# noqa: CR-003`。静默吞异常会让线上故障在日志里完全留不下痕迹。对应审查规则 CR-003（major）。

## §2.4 外部输入不得用 assert 校验

`assert` 在 `python -O` 下会被整体移除，不能作为边界校验手段。对函数外部传入的参数做校验时抛 `ValueError` 或 `TypeError`，并给出可读的错误信息。测试文件里的断言不受本条约束，见《豁免清单》§2.2。对应审查规则 CR-007（minor）。

## §2.5 文件与连接必须纳入上下文管理

`open()` 得到的句柄必须放在 `with` 语句里，数据库连接、网络会话同理。异常路径下如果依赖解释器回收，句柄可能延迟释放，长时间运行的任务会累积到句柄耗尽。对应审查规则 CR-004（major）。

## §3.2 SQL 必须使用参数化查询

任何进入 `execute()` 的 SQL 都不得由 f-string、`%` 格式化、`.format()` 或字符串加法拼接而成，即使用户输入看起来已经校验过。统一使用驱动提供的占位符，把值作为参数元组传入。字符串拼接是注入漏洞最主要的来源，本条为 blocker。对应审查规则 CR-002（blocker）。

## §3.4 外部 HTTP 调用必须设置超时

`requests` 的 `get / post / put / delete / patch` 必须显式传 `timeout=(连接超时, 读取超时)`。不设超时的请求在下游僵死时会一直挂住工作线程，进而拖垮整个服务。内部健康检查接口同样适用。对应审查规则 CR-008（minor）。

## §4.1 凭据禁止写入源码

API Key、数据库口令、私钥、访问令牌一律从环境变量或密钥服务读取，不得以字符串字面量出现在源码、配置样例或注释里。值形如 `your_key_here`、`<PLACEHOLDER>` 的占位符不在此列，判断方法见《豁免清单》§1。凭据一旦进入版本库，轮换之前都应视为已泄漏。对应审查规则 CR-001（blocker）。

## §4.2 日志与打印不得输出敏感字段

`print`、`logger.*`、`logging.*` 的输出内容里不得出现 password、token、secret、id_card、api_key 的完整值。需要定位问题时输出字段名的哈希或后四位，不要输出原文。日志通常会被采集到集中存储，权限比源码仓库更宽，泄漏面更大。对应审查规则 CR-005（major）。测试目录内的调试打印豁免，见《豁免清单》§2.1。
