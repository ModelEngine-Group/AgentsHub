# 历史评审结论（节选）

本文件收录十条既往评审记录，供审查时回答「同类问题以前怎么判的」。记录编号在报告里直接引用，格式为「《历史评审结论》R-2026-xx」。所有文件名为演示用虚构路径，不含真实业务代码。

## R-2026-01 · 配置中心读取的密钥未报

规则 CR-001 候选。文件 `config/runtime.py`，值来自 `os.environ.get("PAYMENT_KEY")`。结论：**不报**，判定为合规实现，理由是本条只禁止字面量凭据，环境变量读取正是 §4.1 推荐的做法。该记录用于防止把「出现 api_key 字样」当成命中。

## R-2026-02 · 文件句柄未关闭，判 major

规则 CR-004。文件 `jobs/export.py`，`f = open(path)` 后直接 `json.load(f)`，无 `with`。结论：**上报 major**。理由是导出任务是常驻进程，异常路径下句柄累积会影响后续任务。依据《编码规范 v1.2》§2.5。修复方式为 `with open(path) as f:`。

## R-2026-03 · 硬编码生产密钥，判 blocker

规则 CR-001。文件 `services/billing.py`，`API_KEY = "sk-live-..."`。结论：**上报 blocker**，并要求先轮换密钥再合并。依据《编码规范 v1.2》§4.1。评审记录特别注明：删掉该行不等于修复，密钥已进入 git 历史。

## R-2026-04 · HTTP 调用缺超时，判 minor

规则 CR-008。文件 `clients/notify.py`，`requests.post(url, json=payload)` 无 `timeout`。结论：**上报 minor**，允许随本次提交修复，不单独阻塞合并。依据《编码规范 v1.2》§3.4。

## R-2026-05 · 裸 except 吞异常，判 major

规则 CR-003。文件 `jobs/sync.py`，`except: pass`。结论：**上报 major**。理由是同步失败后没有任何日志，曾导致两天的数据缺口未被发现。依据《编码规范 v1.2》§2.3。

## R-2026-06 · 可变默认参数，判 minor

规则 CR-006。文件 `utils/batch.py`，`def add(batch=[])`。结论：**上报 minor**，不在合并前强制修复，但记入技术债清单。依据《编码规范 v1.2》§1.3。

## R-2026-07 · f-string 拼 SQL，判 blocker

规则 CR-002。文件 `services/order.py`，`cursor.execute(f"SELECT * FROM orders WHERE id = {uid}")`，`uid` 来自请求参数。结论：**上报 blocker**，即使上游做过类型校验也不降级，理由是参数化查询是唯一可验证的防线。依据《编码规范 v1.2》§3.2。该记录是本知识库被引用最多的一条。

## R-2026-08 · assert 校验入参，判 minor

规则 CR-007。文件 `api/handler.py`，`assert age > 0`。结论：**上报 minor**，改用 `raise ValueError`。依据《编码规范 v1.2》§2.4。同文件测试目录里的 `assert` 另按豁免处理。

## R-2026-09 · 日志打印口令，判 major

规则 CR-005。文件 `services/auth.py`，`logger.info(f"password={pwd}")`。结论：**上报 major** 并要求清理历史日志中的同类记录。依据《编码规范 v1.2》§4.2。

## R-2026-10 · 测试文件的调试打印未报

规则 CR-005 候选。文件 `tests/test_auth.py`，`print("token:", TOKEN)`。结论：**不报**，命中《豁免清单》§2.1。该记录是最容易被忽略的一条：扫描器会把它列为候选，但没有知识库就无法判定豁免，会直接产生误报。
