# 历史事故复盘（模板）

> 下面是 4 个**示例**复盘，用来演示「事故 → 规则 → 检查点」的写法。
> 正式使用时请替换为团队真实事故（脱敏），保留同样结构。真实案例的检索命中率远高于通用规则。

## PM-01 拼接 SQL 导致全表泄露

**现象**：查询接口返回了全部用户记录，日志出现 `OR 1=1`。
**根因**：新增的筛选条件用 f-string 拼进 SQL，未走参数化。
**规则**：R-SEC-01；任何 `execute` 的输入必须参数化，动态表名/排序字段走白名单。
**检查点**：diff 中出现 `execute(f"`、`execute("..." +`、`% (` 即拦截。

## PM-02 缓存击穿打垮数据库

**现象**：热点 key 过期瞬间，数据库 QPS 涨 20 倍，接口超时。
**根因**：`if not cache.get(k): cache.set(k, load(k))` 无锁，并发全部回源。
**规则**：R-GEN-08；热点缓存加单飞/互斥锁，过期时间加随机抖动。
**检查点**：新增缓存读取逻辑时，检查是否有并发回源保护。

## PM-03 时区错乱导致对账差一天

**现象**：跨月账单日期偏移，财务对账失败。
**根因**：容器时区 UTC，代码用 `datetime.now()` 生成业务日期，展示端按本地时间截断。
**规则**：R-PY-05；存储与计算统一 UTC，展示层转换，禁止 naive datetime。
**检查点**：新增时间字段/日期截断逻辑时，检查时区来源。

## PM-04 密钥进 Git 历史

**现象**：公开仓库出现云厂商 AK，产生异常调用费用。
**根因**：本地调试把密钥写进 `settings.py` 并提交。
**规则**：R-SEC-06；密钥只走环境变量/密钥管理，提交前 secret scanning。
**检查点**：diff 命中 `AKIA`、`BEGIN PRIVATE KEY`、`password = "..."` 即 P0。

---

## 使用说明

1. 每条复盘必须能提炼出一条**可判定**的规则，否则不要放进知识库。
2. 事故描述脱敏，不写真实客户、账号、金额。
3. 新事故处理完后 48 小时内补充，保持知识库新鲜。
